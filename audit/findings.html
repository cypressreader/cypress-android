Must-fixD7NEWCODE

Auto Backup is on: app data can leave the phone, contradicting "all data stays on your device"

Where
the Capacitor template manifest has android:allowBackup="true" (templates 7.6.2 and 8.6.0 both); neither native/AndroidManifest.release.xml nor extras.xml nor prepare_android.py overrides it (grep for allowBackup in repo: none). The web app's whole state (feeds, saved stories, notes, history, sync code, the user's own relay address) lives in WebView localStorage/IndexedDB under the app data directory, which Auto Backup uploads to the user's Google Drive on Android 6-11 and via device-to-device transfer/cloud backup on 12+.
Should
either set android:allowBackup="false" (add to the <application> tag in both manifests; also tools:replace if the merger complains) or add dataExtractionRules/fullBackupContent that exclude webview/databases/shared_prefs for cloud backup, OR keep it and say so honestly in privacy.html and the Data safety form. Because the sync code is inside that data, excluding it is the safer choice. NEEDS-PHONE to confirm restore behaviour either way.
