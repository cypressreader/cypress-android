# CyPress — Operating Rules (read on every boot)

## 0. Boot sequence (automatic, before any action)
1. **Read `HANDOFF.md` first.** It holds the live state, what is locked, dead ends and the next 3 tasks. Do not ask the user to repeat anything that is in it.
2. Use the map below to go straight to the right file and symbol. Do not scan the repo.
3. The user types just `Continue` in a new session: resume from "Active state" in `HANDOFF.md`.

## 1. What this is
CyPress Reader: privacy-first, magazine-style RSS reader. No accounts, no ads, all data on the device. Web app + Capacitor Android wrapper (`com.cypress.reader`, sideloaded APK). Static hosting on GitHub Pages; no backend (only an optional user-run Cloudflare Worker). Maintainer is technical but wants plain-English explanations: lead with what it means, then the detail.

## 3. Token discipline (non-negotiable)
- **Surgical reads:** never read `www/index.html` whole. `grep -n` the symbol, then Read with `offset`/`limit`, and cut long lines (`cut -c1-300`). Don't re-read a file already read this session.
- **Quiet commands:** tests, builds and linters with quiet output: `node tests/syntax.js | tail -n 25`, `… 2>&1 | tail -n 25`, `--silent`/`-q` where a tool has them. Run only the tests the change needs. Never write new test suites unprompted. Never run audits without approval.
- **Workers — only when the job reads a lot and answers little.** Hand work to a `model: sonnet` worker when it would otherwise dump large output into this chat but come back as a short answer: sweeping greps across many files or naming conventions, pulling a fact out of `TESTING.md` / `HANDOFF-ARCHIVE.md` / `FIXES.md` (28k / 18k / 8k tokens if read whole), running a test suite and reporting only what failed, auditing a branch diff. Ask for the conclusion, not the excerpts. This keeps the bulk out of this chat's context whatever model is running; it only costs *less per token* when the session's own model is the dearer one.
  - **Never** for edits, commits, pushes, releases, or anything needing the locked rules in `HANDOFF.md`.
  - **Never** when the file and line are already known, or the answer is one `grep`: a worker starts cold and must re-read `CLAUDE.md` + `HANDOFF.md` (~4.5k tokens), and its brief plus its report are billed at this session's model. Below roughly a screenful of output, doing it directly is cheaper.
  - A `fork` worker always inherits this session's model, so it never saves on tier — only a named cheaper worker does.
  - No workflows or multi-agent fan-out for routine edits.
- **Failures only, never full logs:** run tests as `node tests/x.js >/dev/null 2>&1 && echo "x ok" || echo "x FAIL"` (loop over several in one command) and only open the output of one that failed.
- **Diffs:** `git diff --stat` / `git log --oneline` first, and `git diff` only on the one file that matters. Never a bare `git diff` on a branch.
- **Big text files are grep-or-append only:** `TESTING.md` (106 KB), `FIXES.md` (32 KB), `HANDOFF-ARCHIVE.md` (70 KB), `whats-new.txt`. Add entries blind with `cat >> file <<'EOF'`, read them with `grep -n` or `tail`, never whole. `www/index.html` is 2 MB (~550k tokens) — reading it whole would spend a third of a weekly budget in one call.
- **Targeted output:** explain what you did and why in plain language, but show only the changed lines, never whole unchanged files.
- Don't read ignored files (see `.claudeignore` / `deny` list in `.claude/settings.json`): lockfiles, `node_modules/`, build output, minified files, sourcemaps, `docs/app/index.html`, `docs/demo.html`, `context/`, `backup/`.
- Replies and debriefs: brief. Use Implemented / Upgraded / Skipped for batches.

## 3b. Which model to run (biggest saver of all)
Opus is the intended main model, but a session can start on any model, so **first know which one you are**: the session's attribution reminder names it (it is also what goes in the commit trailer), and `get_session` confirms it. Don't assume Opus. The largest saving is not delegation, it is not spending the dear model on procedure — so match the work to the model, in **one line in the first reply**, then do as asked either way. **Never switch models unprompted**, and never refuse work because of the model.
- **On Opus, and the whole session is procedure** (the list below): "This is all procedure — `/model claude-sonnet-5-5` would do it for the same result."
- **On Sonnet, and the work is in the 'worth Opus' list:** "This one is Opus work (device-only bug / layout judgment / locked-rule call) — `/model claude-opus-5` if you want it. I'll start either way." If told to carry on, carry on, but lean harder on measurements than on judgment, and say plainly when something is a guess.
- **On Sonnet with procedure, or Opus with Opus work:** say nothing about models and get on with it. No commentary when the fit is already right.
- **Sonnet is enough:** version bump (`APP_VERSION`/`APP_LABEL` + `whats-new.txt` + `node scripts/sync-whats-new.js`), merge to `main` on `build`, `scripts/publish-preview.sh`, handoff trims and archive moves, US-spelling and copy sweeps, adding `TESTING.md` entries, re-running tests, mechanical find-and-replace.
- **Worth Opus:** diagnosing a device-only bug (today's WebView rotation), judging or designing layout, anything touching `fitPage1`/`fitHero`/`layout`/`relayout`, deciding whether a change breaks a locked rule in §7, weighing a dead end.
- **Context re-sends are the quiet cost:** every turn re-sends the whole conversation, so turn 10 costs far more than turn 2 for the same work. Obey the §4 handoff alarm early rather than late — a fresh session at ~4.5k tokens of boot files is cheaper than three more turns on a long one.

## 4. Memory protocol
- **Keep HANDOFF.md lean (token saver):** it is read on every boot. Keep it under ~8 KB: when it grows, move finished/dated items to `HANDOFF-ARCHIVE.md` (never read on boot) and keep only locked rules, open items and the next 3 tasks. Trim whenever it makes sense, as part of the silent save.
- **Silent saving:** whenever a task or bug fix is finished, update `HANDOFF.md` on disk (Working & Locked, Dead Ends, Active State, Next 3 Tasks) and commit it with the work. No announcement needed.
- **Turn counter (mechanical):** the `UserPromptSubmit` hook in `.claude/settings.json` runs `scripts/turn-counter.js`; from the 8th user message of a session it injects a `[turn-counter]` reminder. When you see it, follow the alarm below at once.
- **Auto-handoff alarm:** when a milestone finishes OR the conversation reaches about 8–10 turns, STOP, make sure `HANDOFF.md` is current and committed, then show exactly:

  🛑 **WEEKLY QUOTA CHECKPOINT: START A NEW SESSION** 🛑
  When on a working branch (not `main`), the very first thing under the banner is this 1-click copy line, in a code fence, with the real branch name: `Checkout branch <current-branch-name>, read CLAUDE.md and HANDOFF.md, and Continue.`
  `HANDOFF.md` and `CLAUDE.md` are updated on disk. Open a new session and simply type: `Continue`

  and under it a copy-ready block (in a code fence) containing the current "Active state" and "Next 3 tasks" from `HANDOFF.md`, in case the next chat is not attached to this repo.

## 5. Workflow rules
- Work on feature branches (this session's branch is named in HANDOFF). **Nothing ships until the user says `build` / `merge`.** Preview first (`scripts/publish-preview.sh`), then wait.
- Commit trailers: `Co-Authored-By: <the model named in this session's attribution reminder> <noreply@anthropic.com>` and `Claude-Session: <session url given in the session>`. Use the model the session actually ran on (it changes when the model is switched mid-session), never a name copied from an older commit. Do not commit the untracked `cypress-gemini-audit/` folder. Never use `pkill -f` (it kills your own shell).
- Local test server: start it in the same command that uses it (`(setsid nohup python3 -m http.server 8766 &)` in `docs/`); servers die between commands.
- Verification honesty: a change you cannot verify here (real phone, TTS, install/update, background work) is "implemented, unverified" and gets a `TESTING.md` entry. Bring measurements, not opinions, when disagreeing.
- If something is unclear: make the reasonable fix, note the assumption, don't stop to ask.

## 6. Versioning
Every `APP_VERSION`/`APP_LABEL` bump needs a matching `whats-new.txt` section (plain-language bullets, headed by the bare Android label on its own line, e.g. `1.137`). **New sections go at the END of the file** — the old `CyPress v1.x` blocks at the top are newest-first, but the bare-label sections since 1.4 run oldest to newest, and both the workflow and `sync-whats-new.js` find a section by its label, not its position in the same commit, then `node scripts/sync-whats-new.js`; `tests/syntax.js` fails if out of step. Web stamp is date-based (`2026.10.17a`); Android label is separate (`1.107`). No third scheme.

## 7. Hard rules (do not regress)
- **Accessibility:** no nested interactive elements; every icon-only button has a unique accessible name; dialogs have `role="dialog"`, focus trap, focus-in on open, focus return on close; selection state exposed (`aria-pressed`/radiogroup); tabs have arrow-key navigation; every control keyboard-operable.
- **Privacy:** every third-party request (fonts, favicons, proxies, update checks, news search) must be disclosed on `docs/privacy.html`; prefer removing the request. No tracking. The app never asks for location.
- **Feeds & content:** don't blanket-ban cleartext HTTP from publishers; first-party traffic is HTTPS-only.
- **Copy:** plain language, no jargon (no "RSS", no "rail"); title-case theme names; watch pluralization ("1 story"); **US spelling** everywhere users read it (color, favorite, center, catalog, neighbor, harbor, gray). Leave code identifiers, CSS names and comments alone. The product is "CyPress Reader" on the site; never "Halcyon" in customer-facing text beyond the theme name; no publisher names or pictures on the site; no "free"/ads promises.
- **Performance:** stay fast on low-end devices; stagger background work, throttle re-renders, respect offline/data-saver/low-power modes.
- **Device testing:** audio, widgets, sharing, background refresh, install/update flows need a real phone; log in `TESTING.md`.
