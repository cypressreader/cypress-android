# CyPress — Operating Rules (read on every boot)

## 0. Boot sequence (automatic, before any action)
1. **Read `HANDOFF.md` first.** It holds the live state, what is locked, dead ends and the next 3 tasks. Do not ask the user to repeat anything that is in it.
2. Use the map below to go straight to the right file and symbol. Do not scan the repo.
3. The user types just `Continue` in a new session: resume from "Active state" in `HANDOFF.md`.

## 1. What this is
CyPress Reader: privacy-first, magazine-style RSS reader. No accounts, no ads, all data on the device. Web app + Capacitor Android wrapper (`com.cypress.reader`, sideloaded APK). Static hosting on GitHub Pages; no backend (only an optional user-run Cloudflare Worker). Maintainer is technical but wants plain-English explanations: lead with what it means, then the detail.

## 3. Token discipline (non-negotiable)
- **Surgical reads:** never read `www/index.html` whole. `grep -n` the symbol, then Read with `offset`/`limit`, and cut long lines (`cut -c1-300`). Don't re-read a file already read this session.
- **Quiet commands:** tests, builds and linters with quiet output: `node tests/syntax.js | tail -n 25`, `… 2>&1 | tail -n 25`, `--silent`/`-q` where a tool has them. Run only the tests the change needs. Never write new test suites unprompted. Never run audits without approval.
- **No agents or workflows** for routine edits.
- **Targeted output:** explain what you did and why in plain language, but show only the changed lines, never whole unchanged files.
- Don't read ignored files (see `.claudeignore` / `deny` list in `.claude/settings.json`): lockfiles, `node_modules/`, build output, minified files, sourcemaps, `docs/app/index.html`, `docs/demo.html`, `context/`, `backup/`.
- Replies and debriefs: brief. Use Implemented / Upgraded / Skipped for batches.

## 4. Memory protocol
- **Silent saving:** whenever a task or bug fix is finished, update `HANDOFF.md` on disk (Working & Locked, Dead Ends, Active State, Next 3 Tasks) and commit it with the work. No announcement needed.
- **Turn counter (mechanical):** the `UserPromptSubmit` hook in `.claude/settings.json` runs `scripts/turn-counter.js`; from the 8th user message of a session it injects a `[turn-counter]` reminder. When you see it, follow the alarm below at once.
- **Auto-handoff alarm:** when a milestone finishes OR the conversation reaches about 8–10 turns, STOP, make sure `HANDOFF.md` is current and committed, then show exactly:

  🛑 **WEEKLY QUOTA CHECKPOINT: START A NEW SESSION** 🛑
  When on a working branch (not `main`), the very first thing under the banner is this 1-click copy line, in a code fence, with the real branch name: `Checkout branch <current-branch-name>, read CLAUDE.md and HANDOFF.md, and Continue.`
  `HANDOFF.md` and `CLAUDE.md` are updated on disk. Open a new session and simply type: `Continue`

  and under it a copy-ready block (in a code fence) containing the current "Active state" and "Next 3 tasks" from `HANDOFF.md`, in case the next chat is not attached to this repo.

## 5. Workflow rules
- Work on feature branches (this session's branch is named in HANDOFF). **Nothing ships until the user says `build` / `merge`.** Preview first (`scripts/publish-preview.sh`), then wait.
- Commit trailers: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: <session url given in the session>`. Do not commit the untracked `cypress-gemini-audit/` folder. Never use `pkill -f` (it kills your own shell).
- Local test server: start it in the same command that uses it (`(setsid nohup python3 -m http.server 8766 &)` in `docs/`); servers die between commands.
- Verification honesty: a change you cannot verify here (real phone, TTS, install/update, background work) is "implemented, unverified" and gets a `TESTING.md` entry. Bring measurements, not opinions, when disagreeing.
- If something is unclear: make the reasonable fix, note the assumption, don't stop to ask.

## 6. Versioning
Every `APP_VERSION`/`APP_LABEL` bump needs a matching `whats-new.txt` section (plain-language bullets, newest first, headed by the Android label, e.g. `1.107`) in the same commit, then `node scripts/sync-whats-new.js`; `tests/syntax.js` fails if out of step. Web stamp is date-based (`2026.10.17a`); Android label is separate (`1.107`). No third scheme.

## 7. Hard rules (do not regress)
- **Accessibility:** no nested interactive elements; every icon-only button has a unique accessible name; dialogs have `role="dialog"`, focus trap, focus-in on open, focus return on close; selection state exposed (`aria-pressed`/radiogroup); tabs have arrow-key navigation; every control keyboard-operable.
- **Privacy:** every third-party request (fonts, favicons, proxies, update checks, news search) must be disclosed on `docs/privacy.html`; prefer removing the request. No tracking. The app never asks for location.
- **Feeds & content:** don't blanket-ban cleartext HTTP from publishers; first-party traffic is HTTPS-only.
- **Copy:** plain language, no jargon (no "RSS", no "rail"); title-case theme names; watch pluralization ("1 story"); **US spelling** everywhere users read it (color, favorite, center, catalog, neighbor, harbor, gray). Leave code identifiers, CSS names and comments alone. The product is "CyPress Reader" on the site; never "Halcyon" in customer-facing text beyond the theme name; no publisher names or pictures on the site; no "free"/ads promises.
- **Performance:** stay fast on low-end devices; stagger background work, throttle re-renders, respect offline/data-saver/low-power modes.
- **Device testing:** audio, widgets, sharing, background refresh, install/update flows need a real phone; log in `TESTING.md`.
